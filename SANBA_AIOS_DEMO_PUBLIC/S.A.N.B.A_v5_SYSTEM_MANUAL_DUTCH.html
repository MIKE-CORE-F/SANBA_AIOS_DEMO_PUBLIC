1. Systeemarchitectuur & Soeverein IP

S.A.N.B.A. AI-OS v5.0 combineert een krachtige Python Single-Kernel basis met een optionele, gedistribueerde Erlang OTP Actor-mesh (AGENTS/MCL_BRIDGE/). In deze publieke baseline zijn de meeste componenten demo-stubs; de Erlang-bronnen zijn meegeleverd maar worden door de demoscripts niet gestart. De demo draait lokaal en doet geen cloud-aanroepen.

Kernarchitectuur: De Python-kern beheert de agent-logica, contextinjectie en lokale uitvoering, terwijl de Erlang OTP actor-laag zorgt voor optionele state governance, netwerk-broadcasting en P2P node-communicatie.

  • Lokale Footprint: De demo draait lokaal op hardware (Linux / WSL) en doet geen cloud-aanroepen.
  • Governance: De financial governor past bedraglimieten toe (toestaan / herzien / blokkeren). De groundlaws-engine en de drift-watchdog zijn stubs en controleren nog niets; commando's worden getoetst aan een allowlist.
  • Optionele Mesh / Station Modus: Placeholder voor P2P-clustering. De meegeleverde mesh-demo is een lokaal voorbeeld met twee TCP-nodes zonder authenticatie.

2. Officiële Opstart-Scripts (WSL / Linux)

Navigeer in je Linux / WSL terminal naar de projectmap:

cd /pad/naar/SANBA_AIOS_DEMO_PUBLIC

Gebruik vervolgens het universele boot.sh script om de gewenste modus te starten:

#!/bin/bash
# ==================================================================
# S.A.N.B.A. AI-OS v5.0 - Universal Boot Script
# ==================================================================

echo "=================================================================="
echo " 🚀 S.A.N.B.A. AI-OS v5.0 - STARTING LOCAL DEMO BASELINE"
echo "=================================================================="

if ! command -v python3 &> /dev/null
then
    echo "[ERROR] Python3 kon niet worden gevonden."
    exit 1
fi

if [ "$1" == "--with-mesh" ]; then
    echo "[MESH] Optionele lokale netwerk-node (Station-modus) activeren..."
    python3 DEMO_MULTI_NODE_MESH.py
else
    echo "[INFO] Lokale demo-boot (geen cloud-aanroepen, componenten zijn stubs)."
    python3 AIOS_BOOT.py
fi

echo "=================================================================="
echo " ✨ Systeem operationeel en klaar voor demonstratie!"
echo "=================================================================="

3. Bedieningsknoppen & CLI Input Codes

Gebruik deze commando's in je terminal tijdens de demonstratie om de afzonderlijke lagen en simulaties aan te sturen:

Systeemlaag / Functie Terminal Commando Beschrijving / Demo-Actie
Systeem Boot (Pure Local) ./boot.sh of python3 AIOS_BOOT.py Laadt de democomponenten en meldt welke geladen zijn (de meeste zijn stubs).
Multi-Node Mesh (Station) ./boot.sh --with-mesh of python3 DEMO_MULTI_NODE_MESH.py Draait een lokale demo met twee TCP-nodes (de Erlang-bridge wordt niet gestart).
Smoke tests python3 test_smoke.py Voert 10 controles uit op de commando-guard, orchestrator, financial governor en snapshots.
VPU Mesh Status python3 -m CORE.VPU_MESH.MESH_ROUTER Toont actieve load-balancing over de VPU-threads.
Agent Cockpit python3 -m AGENTS.COCKPIT.AGENT_COCKPIT Opent de interactieve interface voor taaktoewijzing.

4. Demonstratie & IP-Positionering

Hanteer dit stappenplan bij het tonen van het platform aan externe belanghebbenden:

  • Stap 1: Start ./boot.sh om de demo-boot te tonen; die meldt welke componenten geladen zijn en welke stubs zijn.
  • Stap 2: Als er vragen komen over enterprise-netwerken of 'Stations', voer je ./boot.sh --with-mesh uit om het lokale voorbeeld met twee TCP-nodes te tonen. Het is geen clustering-implementatie.
  • Stap 3: Benadruk dat de core-architectuur jouw intellectuele eigendom is en dat netwerk- of station-integraties klantspecifieke uitbreidingen zijn bovenop het soevereine OS.
